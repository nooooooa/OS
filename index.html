1. Computer Hardware & Operating System

Komponen dasar komputer

KomponenFungsi
CPU / ProcessorMenjalankan instruksi program.
Main Memory (RAM)Menyimpan data dan instruksi yang sedang digunakan.
I/O Modules / DevicesMenghubungkan komputer dengan perangkat input dan output.
System BusJalur komunikasi antara CPU, memory, dan I/O.

Operating System berada di antara aplikasi dan hardware. OS bertindak sebagai resource manager, bukan aplikasi biasa.

Application → Operating System → Hardware

Bagaimana OS mengelola memory?

  • Mengalokasikan memory kepada process.
  • Membebaskan memory saat tidak dibutuhkan.
  • Melindungi area kernel.
  • Mengisolasi memory antar-process agar tidak saling mengganggu.

Tambahan konsep: memory hierarchy mencakup cache, main memory (RAM), dan secondary storage. Cache lebih dekat dan umumnya lebih cepat diakses CPU daripada RAM.

2. Instruction Cycle & Interrupt

Instruction cycle

  1. Fetch: CPU mengambil instruksi dari memory menggunakan alamat pada Program Counter (PC).
  2. Decode: CPU menerjemahkan instruksi untuk mengetahui operasi yang harus dilakukan.
  3. Execute: CPU menjalankan instruksi.
  4. Interrupt check: CPU memeriksa apakah ada interrupt yang perlu ditangani, lalu siklus berulang.

Interrupt

Interrupt adalah sinyal yang memberi tahu CPU bahwa ada kejadian yang membutuhkan perhatian. Interrupt memungkinkan OS mengambil kembali kontrol CPU.

Contoh: program berjalan → keyboard menerima input → keyboard mengirim interrupt → CPU menyimpan kondisi program → OS menangani input → program dilanjutkan.

Beberapa interrupt sekaligus

  • Priority: interrupt berprioritas tinggi ditangani lebih dahulu.
  • Masking: interrupt tertentu dapat dinonaktifkan sementara saat CPU menangani tugas yang lebih penting.

Jika perangkat I/O mengirim interrupt, CPU menyimpan context program yang sedang berjalan. OS menangani event I/O, kemudian program sebelumnya dapat dilanjutkan.

3. OS sebagai Extended Machine & System Call

OS disebut extended machine karena menyembunyikan detail hardware yang rumit dan menyediakan abstraksi/interface yang lebih mudah digunakan.

Contoh abstraksi

  • File: program cukup membuka, membaca, atau menulis file tanpa mengatur detail fisik disk secara langsung.
  • Process: program tidak perlu mengatur CPU sendiri; OS menyediakan konsep process dan mengatur pergantian eksekusi.

System call adalah mekanisme program meminta layanan dari OS. Program umumnya berjalan dalam user mode; saat system call dilakukan, CPU berpindah ke kernel mode untuk menjalankan layanan OS.

Application (user mode) → System Call → Kernel mode → OS service → Return

Resource yang dikelola OS

CPU, main memory, I/O devices, files/storage, processes, dan network resources.

Batch system vs Time-sharing

4. Process, PCB, dan Process States

Process adalah program yang sedang dieksekusi beserta kondisi dan resource yang dibutuhkan.

State utama process

PerpindahanAlasan
Ready → RunningScheduler memberikan CPU.
Running → ReadyTime slice habis atau process di-preempt.
Running → BlockedProcess menunggu I/O/event.
Blocked → ReadyI/O atau event selesai.

Process Control Block (PCB)

Struktur data OS yang menyimpan PID, process state, program counter, CPU registers, informasi scheduling, informasi memory, dan status I/O. PCB membantu OS menghentikan sementara dan melanjutkan process.

Creation, hierarchy, dan termination

Process dapat dibuat saat komputer dinyalakan, program dijalankan, atau process lain membuatnya. Parent process membuat child process; hubungan ini membentuk process tree. Saat process selesai, OS melakukan cleanup: membebaskan memory, menutup file, dan melepaskan resource.

Multiprogramming, suspend, dan swap

Multiprogramming menempatkan beberapa program di memory agar CPU dapat menjalankan process lain saat sebuah process menunggu I/O. Swap out memindahkan process dari RAM ke storage; swap in memasukkannya kembali. Suspend berarti process ditangguhkan sementara.

5. Process vs Thread

Thread adalah unit eksekusi di dalam process. Satu process dapat memiliki beberapa thread.

Shared dalam processPrivate tiap thread
Address space, data, dan resource seperti file terbuka.Stack, registers, dan program counter.

Keuntungan thread

  • Responsiveness: aplikasi tetap responsif saat thread lain bekerja.
  • Resource sharing: thread dalam process yang sama mudah berbagi data.
  • Economy: pembuatan dan context switch thread umumnya lebih ringan daripada process.
  • Parallelism: thread dapat berjalan di beberapa core jika didukung sistem.
Shared memory perlu sinkronisasi. Tanpa pengaturan yang benar, dua thread dapat menimbulkan race condition.

Model implementasi thread

ModelPengelolaKelebihan / kelemahan

KLT (Kernel-Level Thread)Kernel OS.Kernel menjadwalkan tiap thread; thread lain dapat berjalan saat satu thread blocked. Overhead lebih tinggi karena melibatkan kernel.

6. Multiprocessor & Distributed Systems

Shared-memory multiprocessor

Dua atau lebih processor berbagi memory utama. Setiap processor dapat memiliki cache sendiri.

  • UMA: waktu akses memory relatif sama bagi semua processor.
  • NUMA: waktu akses berbeda tergantung lokasi memory.
  • Cache coherence: menjaga agar salinan data pada cache processor tetap konsisten.

Organisasi OS multiprocessor

  • Separate OS: tiap processor memiliki OS/supervisor sendiri.
  • Master-slave: satu processor mengatur OS, processor lain menjalankan tugas.
  • SMP (Symmetric Multiprocessing): processor memiliki kedudukan setara.

Sinkronisasi & penjadwalan CPU

  • Spinlock: processor menunggu (busy-wait) sampai lock tersedia.
  • Test-and-set: operasi atomik untuk memeriksa sekaligus mengubah lock.
  • Barrier: membuat processor/thread menunggu sampai semua peserta mencapai titik sinkronisasi.
  • Time sharing: processor dibagi berdasarkan waktu.
  • Space sharing: processor dialokasikan untuk pekerjaan tertentu.
  • Gang scheduling: thread terkait dijalankan bersama-sama.
  • Processor affinity: mempertahankan process pada processor yang sama untuk mengurangi biaya migrasi/cache miss.

Multicore & real-time

Load balancing membagi beban antar-core. Migration memindahkan process/thread, tetapi dapat menimbulkan biaya karena cache perlu diisi kembali.

Hard real-timeSoft real-time
Deadline harus dipenuhi; keterlambatan tidak dapat diterima.Keterlambatan sesekali masih dapat ditoleransi.
  • RMS: prioritas tetap berdasarkan periode task; periode lebih pendek mendapat prioritas lebih tinggi.
  • EDF: task dengan deadline paling dekat mendapat prioritas tertinggi.

Multicomputer & middleware

Multicomputer terdiri dari node yang masing-masing memiliki processor dan memory sendiri serta terhubung melalui jaringan.

  • Message passing: node bertukar pesan.
  • RPC: memanggil prosedur pada komputer lain.
  • DSM: abstraksi seolah-olah memory digunakan bersama.

Middleware adalah perangkat lunak perantara komunikasi aplikasi terdistribusi. Contoh: RPC middleware dan Message-Oriented Middleware (MOM).

7. Konsep pendukung soal coding

Process creation dengan fork()

fork() membuat child process. Nilai baliknya: negatif jika gagal, 0 pada child, dan PID child pada parent. Parent dapat memakai wait()/waitpid() agar menunggu child selesai.

Thread dan mutex

pthread_create() membuat thread, pthread_join() menunggu thread selesai. Mutex melindungi critical section agar hanya satu thread mengakses data bersama pada satu waktu.

Producer–consumer / bounded buffer

Producer memasukkan item ke buffer terbatas; consumer mengambilnya. Mutex melindungi buffer. Condition variable membuat producer menunggu saat buffer penuh (not_full) dan consumer menunggu saat kosong (not_empty).

Parallel array sum

Array dibagi menjadi beberapa bagian untuk worker thread. Tiap worker menghitung partial sum, lalu menambahkan hasil ke total bersama dengan perlindungan mutex.

Rumus dasar CPU Scheduling

Completion / Finish Time

FT = waktu ketika process selesai pada Gantt Chart

Turnaround Time

TAT (Tr) = FT − AT

Total waktu sejak process datang sampai selesai.

Waiting Time

WT = TAT − BT = FT − AT − BT

Total waktu process menunggu di ready queue.

Normalized Turnaround Time

Normalized TAT = TAT ÷ BT

Average / Mean

Average TAT = ΣTAT ÷ jumlah process
Average WT = ΣWT ÷ jumlah process
Average Normalized TAT = Σ(TAT/BT) ÷ jumlah process

Rumus dan aturan algoritma

FCFS Non-preemptive

Start = max(FT sebelumnya, AT)
Urutan berdasarkan AT paling awal

SPN / SJF Non-preemptive

Pilih BT terkecil dari process yang sudah tiba

SRT Preemptive

Remaining Time = BT − waktu yang telah dieksekusi
Pilih remaining time paling kecil

Round Robin Preemptive

Eksekusi per giliran = min(q, remaining time)
Remaining baru = remaining lama − eksekusi

Jika masih ada sisa setelah quantum habis, process masuk ke belakang ready queue.

HRRN Non-preemptive

Response Ratio = (WT + BT) ÷ BT
= 1 + (WT ÷ BT)

Pilih response ratio terbesar. WT dihitung dari waktu process tiba sampai keputusan scheduling dibuat.

Rata-rata scheduling

Mean = total nilai seluruh process ÷ jumlah process

1. fork() — Parent & Child Process

Child mencetak PID dan angka 1 sampai N. Parent menunggu child selesai dengan wait().

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    int n;
    printf("NIM NAMA LENGKAP\n");
    fflush(stdout);

    if (scanf("%d", &n) != 1) return 1;

    pid_t pid = fork();
    if (pid < 0) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        printf("child %d\n", getpid());
        for (int i = 1; i <= n; i++) printf("%d\n", i);
        fflush(stdout);
        exit(0);
    } else {
        int status;
        pid_t childpid = wait(&status);
        printf("parent self %d child %d\n", getpid(), childpid);
        printf("DONE\n");
    }
    return 0;
}

Ganti NIM NAMA LENGKAP dengan identitas roster sendiri. fflush(stdout) memastikan baris pertama tercetak sebelum fork.

2. pthread + Mutex — Shared Sum

Worker mengambil mutex, menambah sequence, mencetak TID, dan menambahkan nilai ke shared sum.

#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>

long sum = 0, seq = 0;
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

void *worker(void *arg) {
    int i = *(int *)arg;
    pthread_mutex_lock(&lock);

    seq++;
    printf("lock %ld\n", seq);
    printf("tid %lu\n", (unsigned long)pthread_self());
    sum += (i + 1);

    pthread_mutex_unlock(&lock);
    return NULL;
}

int main(void) {
    int n;
    printf("NIM NAMA LENGKAP\n");
    fflush(stdout);
    if (scanf("%d", &n) != 1 || n < 0) return 1;

    pthread_t *threads = malloc(n * sizeof(pthread_t));
    int *ids = malloc(n * sizeof(int));
    printf("main %lu\n", (unsigned long)pthread_self());

    for (int i = 0; i < n; i++) {
        ids[i] = i;
        pthread_create(&threads[i], NULL, worker, &ids[i]);
    }
    for (int i = 0; i < n; i++) pthread_join(threads[i], NULL);

    printf("sum %ld\n", sum);
    free(threads); free(ids);
    pthread_mutex_destroy(&lock);
    return 0;
}
Mutex membuat bagian update seq dan sum menjadi critical section yang aman dari race condition.

3. Producer–Consumer — Bounded Buffer

Buffer kapasitas 8. Producer menunggu saat penuh; consumer menunggu saat kosong.

#include <stdio.h>
#include <pthread.h>
#define CAP 8

int buf[CAP], in=0, out=0, count=0, n;
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t not_full = PTHREAD_COND_INITIALIZER;
pthread_cond_t not_empty = PTHREAD_COND_INITIALIZER;

void *producer(void *arg) {
    printf("prod %lu\n", (unsigned long)pthread_self());
    for (int i=1; i<=n; i++) {
        pthread_mutex_lock(&m);
        while (count == CAP) pthread_cond_wait(&not_full, &m);
        buf[in] = i;
        in = (in + 1) % CAP;
        count++;
        pthread_cond_signal(&not_empty);
        pthread_mutex_unlock(&m);
    }
    return NULL;
}

void *consumer(void *arg) {
    printf("cons %lu\n", (unsigned long)pthread_self());
    for (int i=1; i<=n; i++) {
        pthread_mutex_lock(&m);
        while (count == 0) pthread_cond_wait(&not_empty, &m);
        int value = buf[out];
        out = (out + 1) % CAP;
        count--;
        pthread_cond_signal(&not_full);
        pthread_mutex_unlock(&m);
        printf("%d\n", value);
    }
    return NULL;
}

int main(void) {
    printf("NIM NAMA LENGKAP\n");
    fflush(stdout);
    if (scanf("%d", &n) != 1 || n < 0) return 1;
    pthread_t prod, cons;
    pthread_create(&prod, NULL, producer, NULL);
    pthread_create(&cons, NULL, consumer, NULL);
    pthread_join(prod, NULL);
    pthread_join(cons, NULL);
    return 0;
}

Pola penting: lock mutex → cek kondisi dengan while → tunggu/signal condition variable → unlock mutex.

4. Parallel Array Sum — Multiple Workers

Array dibagi menjadi potongan kontigu yang relatif merata. Setiap worker menghitung partial sum, lalu menggabungkannya dengan mutex.

#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <unistd.h>

int *arr, m, n;
long total = 0;
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

typedef struct { int id; } ThreadArg;

void *worker(void *arg) {
    int i = ((ThreadArg *)arg)->id;
    int start = i * m / n;
    int end = (i + 1) * m / n;
    long partial = 0;

    for (int j=start; j<end; j++) partial += arr[j];
    printf("worker %lu part %ld\n",
           (unsigned long)pthread_self(), partial);

    pthread_mutex_lock(&lock);
    total += partial;
    pthread_mutex_unlock(&lock);
    return NULL;
}

int main(void) {
    printf("NIM NAMA LENGKAP\n");
    fflush(stdout);
    if (scanf("%d %d", &n, &m) != 2 || n <= 0 || m < 0) return 1;

    printf("cpus %ld\n", sysconf(_SC_NPROCESSORS_ONLN));
    printf("main %lu\n", (unsigned long)pthread_self());

    arr = malloc((size_t)m * sizeof(int));
    for (int i=0; i<m; i++) scanf("%d", &arr[i]);

    pthread_t *threads = malloc(n * sizeof(pthread_t));
    ThreadArg *args = malloc(n * sizeof(ThreadArg));
    for (int i=0; i<n; i++) {
        args[i].id = i;
        pthread_create(&threads[i], NULL, worker, &args[i]);
    }
    for (int i=0; i<n; i++) pthread_join(threads[i], NULL);

    printf("total %ld\n", total);
    free(arr); free(threads); free(args);
    pthread_mutex_destroy(&lock);
    return 0;
}
